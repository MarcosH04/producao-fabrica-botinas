ANP Fuel ETLO preço de cada posto do Brasil, toda semana, num banco pronto para análise

Um pipeline que baixa a Série Histórica de Preços de Combustíveis da ANP, limpa milhões de linhas com Pandas e carrega tudo num data warehouse PostgreSQL. O Apache Airflow roda a carga sozinho todo sábado, e o Docker sobe o ambiente inteiro com três comandos.

Perguntas que viram uma consulta

Os dados públicos da ANP chegam como CSVs enormes, com layout que muda de ano para ano. Depois do pipeline, cada uma destas perguntas é um SELECT simples.

Qual o preço médio da gasolina por estado a cada semana?

anp.vw_preco_medio_semanal_uf

Em qual mês o etanol compensou mais que a gasolina?

anp.vw_paridade_etanol_gasolina_uf

Qual município tem o diesel mais barato?

anp.vw_preco_medio_mensal_municipio

Da ANP ao banco em cinco tarefas

As duas DAGs seguem a mesma sequência. Com Dynamic Task Mapping, o Airflow cria uma tarefa por arquivo e processa os arquivos em paralelo.

Camada 1

Raw

data/raw/

O arquivo exatamente como veio da ANP. Nunca é alterado, para dar para reprocessar quando uma regra mudar.

Camada 2

Processed

data/processed/*.parquet

Dados limpos e tipados em Parquet, com um JSON de estatísticas de qualidade ao lado de cada arquivo.

Camada 3

Warehouse

anp.precos_combustiveis

Tabela de fatos com chave por posto, produto e dia, tabela de auditoria e as views analíticas.

O portão de qualidade

Linhas com CNPJ inválido, data inválida ou preço fora de R$ 0,50 a R$ 50,00 são rejeitadas e contadas. Se mais de 20% do arquivo for rejeitado, a tarefa falha em vez de carregar dado ruim. Escolha um arquivo de exemplo e veja as regras do transform.py rodando aqui.

Decisões de projeto

        
O que separa um script que funciona uma vez de um pipeline que roda toda semana sem ninguém olhar.

      

      

        
Idempotente
A carga faz COPY numa tabela temporária e depois INSERT ... ON CONFLICT DO UPDATE. Rodar o mesmo arquivo duas vezes não duplica nada, e só as linhas que a ANP revisou são reescritas.

        
Resistente a layout
A ANP mudou formato, codificação e nome de coluna ao longo dos anos. O código normaliza nomes, detecta UTF-8 ou Latin-1 e o separador, e falha cedo com mensagem clara se aparecer um layout novo.

        
Passa caminho, não dado
As tarefas do Airflow trocam apenas caminhos de arquivo pelo XCom, nunca DataFrames. O banco interno do Airflow não incha.

        
Auditável
Cada arquivo carregado gera uma linha em anp.etl_execucoes com linhas lidas, rejeitadas, duplicadas e afetadas. Cada preço guarda o arquivo_origem.

        
DAGs leves
O pandas só é importado dentro das tarefas, então o Airflow lê a pasta de DAGs rápido, mesmo relendo a cada poucos segundos.

        
Testado no CI
O GitHub Actions roda Ruff, pytest e a validação do docker-compose.yml a cada push.

      

    

  


  

    

      

        
Roda no seu computador

        
Só precisa de Docker e Git. O repositório traz um guia passo a passo para quem nunca usou Docker nem Airflow, com instalação no Windows do zero.

      

      

        
bash


$ git clone https://github.com/MarcosH04/anp-fuel-etl.git
$ cd anp-fuel-etl && cp .env.example .env
$ docker compose build
$ docker compose up airflow-init   # roda uma vez
$ docker compose up -d

      

      

        
AirflowAbra localhost:8080, ative anp_incremental_semanal e dispare a DAG.

        
BancoConecte em localhost:5433, base anp.

        
Sem Airflowpython -m anp_etl.cli last4weeks roda o ETL direto pela linha de comando.
